# Dentsply Sirona

> Dentsply Sirona is the world's largest manufacturer of professional dental products and
> technologies. Its public API surface has two halves that behave nothing alike: DS Core, a cloud
> platform whose API reference sits behind a partner login at open.dscore.com, and the Dentsply
> Sirona Imaging APIs, three real OpenAPI 3.0 contracts published openly on GitHub under MIT and
> Apache licences. Generated by API Evangelist from the artifacts in this repository; a probe of
> https://www.dentsplysirona.com/llms.txt and https://open.dscore.com/llms.txt on 2026-09-06 found
> no provider-published llms.txt.

## APIs

- [DS Core API](https://open.dscore.com/): Cloud platform API for practice-management vendors, lab-management vendors and DSOs — patient data synchronisation, scan and imaging exchange, lab order routing, file and comment exchange, and SSO user provisioning. Base https://api.dscore.com. No public contract; the reference requires an approved partner account.
- [Intraoral Imaging Modality API](https://github.com/dsimaging/dsio-modality-api): 17 operations for driving Dentsply Sirona intraoral sensors — device discovery, acquisition sessions, image retrieval, and two Server-Sent Events channels. Runs as a LOCAL service on the practice workstation at https://localhost:43809/api/dsio/modality/v1.
- [Intraoral Imaging Filters API](https://github.com/dsimaging/dsio-filters-api): 9 operations for applying Select, Supreme and AE filters to 16-bit grayscale images from the Modality API. Also local, at https://localhost:43809/api/dsio/filters/v1.
- [Intraoral Exposure API](https://github.com/dsimaging/io-exposure-service): 4 read-only operations for retrieving X-ray tube generator exposure dose records. A specification for generator vendors to implement rather than a service Dentsply Sirona hosts. Repository archived.

## What this provider does NOT publish

- No MCP server, no A2A agent card, no llms.txt of their own.
- No AsyncAPI and no webhooks. The only event surface is two Server-Sent Events channels inside the Modality OpenAPI.
- No idempotency contract on any write operation.
- No error body on any 4xx/5xx response — the status code is the whole error contract.
- No published rate limits, no API pricing, no deprecation policy, no SLA.
- No DICOM anywhere in three intraoral imaging contracts.
